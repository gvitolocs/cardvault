# Pokoin Social Autoposter Workflow

Pokoin can post marketplace card updates to a Telegram channel and to X/Twitter
through protected Vercel API functions. These functions are server-only and must
never expose provider tokens to Flutter or browser clients.

Social copy may be generated by the dedicated peer2 social post agent. This is
separate from the Pokontact support chatbot: do not reuse `/chat` for autoposts.
The social route is `/social-post`, and the Vercel gateway route for copy-only
generation is `/api/social-post-agent`.

## Endpoints

Manual post:

```bash
curl -X POST "https://pokoin.com/api/social-autopost" \
  -H "Content-Type: application/json" \
  -H "x-pokoin-social-secret: $SOCIAL_AUTOPOST_SECRET" \
  -d '{
    "targets": ["telegram", "x"],
    "message": "Hot on Pokoin: Rare Leafeon is trending today.",
    "cardId": "316600",
    "useAgent": true,
    "dryRun": true
  }'
```

Hot-card post:

```bash
curl "https://pokoin.com/api/social-autopost/hot-card?targets=telegram,x&window=24h&dryRun=true" \
  -H "Authorization: Bearer $SOCIAL_AUTOPOST_SECRET"
```

Copy-only agent call:

```bash
curl -X POST "https://pokoin.com/api/social-post-agent" \
  -H "Content-Type: application/json" \
  -H "x-pokoin-social-secret: $SOCIAL_AUTOPOST_SECRET" \
  -d '{
    "targets": ["telegram", "x"],
    "card": {
      "cardId": "316600",
      "name": "Leafeon",
      "setName": "Prismatic Evolutions"
    }
  }'
```

Set `dryRun` to `false` or omit it only when you want the function to call the
real provider APIs. Do not run live posts from local tests without explicit
operator approval.

## Authentication

The endpoints accept any one of these protections:

- `x-pokoin-social-secret: $SOCIAL_AUTOPOST_SECRET`
- `Authorization: Bearer $SOCIAL_AUTOPOST_SECRET`
- `Authorization: Bearer $CRON_SECRET`, for Vercel Cron-style calls
- a Firebase bearer token for an account allowed by the existing marketplace
  debug/admin allowlist

Use a long random `SOCIAL_AUTOPOST_SECRET`. Keep `CRON_SECRET` only if a future
Vercel Cron entry will call the hot-card endpoint.

## Peer2 Social Agent

The support chatbot uses the Pokontact `/chat` endpoint. Social autoposting uses
a dedicated peer2 route instead:

```text
http://130.162.242.213:8787/social-post
```

Vercel env:

```text
SOCIAL_AGENT_ENDPOINT=http://130.162.242.213:8787/social-post
SOCIAL_AGENT_TOKEN=<shared token for peer2 social route>
SOCIAL_AGENT_TIMEOUT_MS=6000
```

`SOCIAL_AGENT_ENDPOINT` can also be supplied as `ORACLE_SOCIAL_AGENT_URL`. The
token can also be supplied as `ORACLE_SOCIAL_AGENT_TOKEN`. Do not reuse
`POKONTACT_SERVICE_URL/chat` as the social endpoint.

The social agent is instructed to:

- write as the Pokoin social post agent, not as Poko/Pokontact support chat;
- use a collector-friendly, confident, concise Pokoin marketplace voice;
- use only supplied card, price, listing, hot-score, and URL data;
- never invent prices, listings, stock, sales, rarity, or popularity;
- include the canonical Pokoin URL exactly once when supplied;
- keep X copy at 280 characters or less;
- keep Telegram copy richer but safe for a 1024-character photo caption;
- avoid support-chat phrases such as "I can help" or follow-up questions;
- return JSON with `telegramText` and `xText`.

If `SOCIAL_AGENT_TOKEN` is missing, peer2 is down, the model times out, or the
agent returns invalid content, the autoposter uses deterministic fallback copy and
continues. Agent failure should not block dry runs or live posting.

## Telegram Setup

1. Create the bot with BotFather and copy the bot token into
   `TELEGRAM_BOT_TOKEN`.
2. Add the bot as an administrator on the Telegram channel.
3. Give the bot permission to post messages.
4. Set `TELEGRAM_CHANNEL_ID` to the channel username such as `@pokoin`, or to
   the numeric channel id.

The integration uses Telegram Bot API `sendMessage` for text posts and
`sendPhoto` when a public card image URL is available. For photo posts the
server downloads the card image and uploads the file to Telegram, instead of
asking Telegram to fetch the URL directly. This avoids Telegram crawler/fetch
failures on protected or transformed image URLs. Telegram captions are trimmed
to 1024 characters; text-only messages are trimmed to 4096 characters.

## X/Twitter Setup

Create an X developer app and configure user-context OAuth 2.0. Posting to
`POST https://api.x.com/2/tweets` requires user authorization, not app-only
bearer auth. The access token must include:

```text
tweet.write
tweet.read
users.read
media.write
```

Request `offline.access` if token refresh is managed by an operator or another
service outside this repo. Store the current user access token in
`X_OAUTH2_ACCESS_TOKEN` or `X_ACCESS_TOKEN` (aliases `X_USER_ACCESS_TOKEN` and
`X_BEARER_TOKEN` are also read). The function sends a lightweight JSON payload:

```json
{ "text": "..." }
```

Posts are trimmed to 280 characters. When a card image URL is available, the
server downloads the image, uploads it through X media upload, and attaches the
returned `media_id` to `POST /2/tweets`. If X returns an auth error, verify the
token is user-context OAuth and includes `media.write` in addition to post
scopes.

OAuth 1.0a user tokens are also supported. If using the X "Access Token" and
"Access Token Secret" pair, configure all of these from the same developer app:

```text
X_API_KEY
X_API_SECRET
X_ACCESS_TOKEN
X_ACCESS_TOKEN_SECRET
```

The token pair alone is not enough; OAuth 1.0a requests must also be signed with
the app API key and API key secret. With OAuth 1.0a configured, the integration
uploads the card image to `https://upload.twitter.com/1.1/media/upload.json` and
then creates the post with X API v2.

## Required Environment

```text
SOCIAL_AUTOPOST_SECRET
SOCIAL_AGENT_ENDPOINT
SOCIAL_AGENT_TOKEN
TELEGRAM_BOT_TOKEN
TELEGRAM_CHANNEL_ID
X_ACCESS_TOKEN
X_OAUTH2_ACCESS_TOKEN
X_OAUTH2_REFRESH_TOKEN
# accepted alias when configured in Vercel with this name
X_BEARER_TOKEN
X_API_KEY
X_API_SECRET
X_ACCESS_TOKEN_SECRET
PUBLIC_SITE_URL
MARKETPLACE_DATABASE_URL
FIREBASE_PROJECT_ID
FIREBASE_CLIENT_EMAIL
FIREBASE_PRIVATE_KEY
```

`CRON_SECRET` is optional unless a scheduler is configured. `PUBLIC_SITE_URL`
defaults to `https://pokoin.com`. `SOCIAL_AGENT_ENDPOINT` defaults to peer2
`/social-post`; `SOCIAL_AGENT_TOKEN` is required before the agent is called.

## Deployment Notes

Do not deploy from this workflow unless explicitly instructed. When a deployment
is requested later, keep `deploy-pokoin-web.sh`, `vercel.json`, and
`server/api-route-manifest.js` aligned so the Vercel build and Oracle API server
can both load:

- `api/social-autopost.js`
- `api/social-autopost-hot-card.js`
- `api/social-post-agent.js`
- `api/_social_autoposter.js`
- `services/pokontact/server.js` with the `/social-post` route

The current change does not add a Vercel cron schedule. Add one only after the
posting cadence and channel approval are decided.
